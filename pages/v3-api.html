The API follows the same resource model used by the web console rather than maintaining a separate integration representation. - That matters because an external application can work with the same identifiers, ownership groups, and relationships that operators already see inside Nova Vector. image: /assets/img/v3/features/11-automation-and-integration/open-api.png image_alt: Nova Vector OpenAPI documentation caption: The OpenAPI interface documents supported platform resources and operations. - eyebrow: Authentication heading: Integrate through the same identity boundary used by the platform paragraphs: - User-facing and service integrations are designed around the platform identity layer rather than anonymous database access. Keycloak provides the user login foundation, and platform services validate active tokens and use roles, permissions, and groups when authorizing requests. - Service-account and identity-provider design are implementation concerns that should be confirmed for the customer's environment, especially where external applications need long-lived unattended access. image: /assets/img/v3/architecture/06-user-authentication.png image_alt: Nova Vector user and service authentication architecture caption: API authorization sits within the same identity architecture as interactive platform access. - eyebrow: Commands heading: Make remote actions observable instead of treating submission as success paragraphs: - Device commands are defined as platform resources and can carry fixed or calculated values. When a command is submitted, the software request enters the command path and can be observed independently from the eventual response of a remote device. - This distinction is deliberate. A successful HTTP request means the platform accepted the request; it does not prove that a remote network, edge node, controller, or physical process completed the action atomically. image: /assets/img/v3/features/11-automation-and-integration/commands.png image_alt: Nova Vector device command definitions caption: Reusable command definitions provide a managed entry point for device actions. - eyebrow: Provisioning and automation heading: Use APIs to build repeatable environments and integration workflows paragraphs: - Public APIs can create profiles, devices, channels, industrial-adapter connections, and related bindings. The simulator tooling uses these same interfaces to provision and remove complete reference environments in a repeatable way. - Scheduled jobs, Node-RED workflows, MQTT, HTTP, and WebSocket can complement REST when the integration needs recurring, event-driven, or low-code behavior rather than a simple request-response exchange. image: /assets/img/v3/features/11-automation-and-integration/schedules.png image_alt: Nova Vector scheduled jobs caption: Schedules provide a managed way to repeat commands and operational jobs at configured intervals. related: - label: Integrations url: /integrations/ - label: Developers url: /developers/ - label: Platform Architecture url: /architecture/ ---
