The platform reads OPC UA, Modbus TCP, and BACnet/IP, receives SNMP traps, accepts MQTT, HTTP, and WebSocket, and connects long-range, low-power sensors through its LoRaWAN network server. CoAP is in pilot. - Write behavior, security, discovery, and command handling differ per adapter and are documented for each one. image: /assets/img/v3/features/01-device-connectivity/protocol-catalog.png image_alt: Nova Vector protocol catalog caption: Connectivity documentation follows the actual adapter and protocol configuration model. - eyebrow: Deployment and operations heading: Keep production guidance separate from the development installation paragraphs: - The scripted installation is meant for development and demonstration. Production deployments are prepared and hardened per project, including ports, secrets, certificates, administration consoles, monitoring, backups, and network access. - The standard installation is Docker Compose on one x86-64 Linux server. Kubernetes, for example with Rancher, is delivered as a project service, and isolated or air-gapped networks are prepared per installation. image: /assets/img/v3/architecture/01-high-level.png image_alt: Nova Vector deployment architecture caption: Deployment documentation distinguishes the central platform, edge nodes, field equipment, and external systems. - eyebrow: Security heading: Document what is enabled by default and what is designed for the project paragraphs: - Keycloak provides single sign-on, roles per module, and groups that keep plants and sites apart. Two-factor login is available for every user, and Keycloak can connect to LDAP, Active Directory, or another identity provider. - Company-directory integration, password policy, audit requirements, certificate management, and access to administration tools are decided for each deployment, and the documentation lists them as part of the security review. image: /assets/img/v3/features/12-security-and-administration/two-factor.png image_alt: Nova Vector two-factor authentication settings caption: Security documentation distinguishes available controls from controls enabled or enforced by default. - eyebrow: Troubleshooting and integration heading: Follow the path a message or command actually takes paragraphs: - Architecture diagrams for telemetry, events, commands, device authentication, and user authentication make troubleshooting concrete, because they show which component owns each step. - The same approach applies to API and edge troubleshooting. Start from the resource and the message path, then inspect the adapter, service, broker, storage layer, or edge node responsible for that stage. image: /assets/img/v3/architecture/03-telemetry-path.png image_alt: Nova Vector telemetry path caption: The telemetry diagram is a practical map for both implementation and troubleshooting. related: - label: Developers url: /developers/ - label: Platform Architecture url: /architecture/ - label: REST API url: /api/ ---
