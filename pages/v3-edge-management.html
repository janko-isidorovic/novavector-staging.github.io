The goal is to make onboarding repeatable when a project grows from a few sites to many similarly configured locations. - Node types define which software bundles and agent settings belong on a particular class of edge computer. That creates a governed baseline for sites that perform the same role instead of relying on individually maintained machines. image: /assets/img/v3/features/07-edge-management/node-state.png image_alt: Nova Vector edge node state view caption: Each node keeps its identity, type, desired software state, and operating status in the fleet view. - eyebrow: Software catalog heading: Treat edge software as an approved deployment artifact paragraphs: - EdgeX runtimes, the local operator console, Edge AI runtime, simulator systems, and other approved service bundles can be stored in the platform artifact catalog. The deployment workflow checks source, size, checksum, signature, compatibility, and configured parameters before software is pushed toward a node. - This separates the question of what software is allowed from the mechanics of installing it. Operators work from approved catalog entries rather than arbitrary container references entered at rollout time. image: /assets/img/v3/features/07-edge-management/rollout-board.png image_alt: Nova Vector edge rollout board caption: Rollouts expose deployment state across the selected nodes rather than hiding installation behind a one-click action. - eyebrow: Controlled rollout heading: Update groups of nodes without changing the entire fleet at once paragraphs: - Group rollouts use bounded concurrency and health checks so an update can progress in controlled batches. Operators can define failure thresholds, retry failed nodes, restore a previous desired state, or roll back when the new software does not behave as expected. - The current fleet-management capability is an integrated beta feature. It is appropriate for controlled early-adopter deployments and should not be represented as a fully mature general-purpose endpoint-management product. image: /assets/img/v3/features/07-edge-management/rollout-board.png image_alt: Edge software rollout status in Nova Vector caption: The rollout board makes deployment progress, failures, and recovery actions visible to the operator. - eyebrow: Site resilience heading: Keep essential operator access and software available at the site paragraphs: - A managed node can expose a local operator console for approved site-side operations even when central connectivity is limited. A site-local container registry can retain required images inside the site so nodes do not depend on external registry access during an isolated deployment. - The platform can also show EdgeX devices and data from the node, helping central and local teams work from the same device context when troubleshooting a remote site. image: /assets/img/v3/features/07-edge-management/local-console.png image_alt: Nova Vector local edge operator console caption: The local console provides site-side visibility into node health and approved workloads. - eyebrow: Network boundaries heading: Distinguish outbound node control from connections that still need site reachability paragraphs: - Telemetry, node status, AI results, and deployment commands use the node's outbound MQTT session, which works through common NAT and firewall arrangements. Installation over SSH, EdgeX device setup, browser access to site consoles, and remote sessions still require the platform or user browser to reach the node address. - That distinction matters when designing VPNs, routing, and firewall rules. Edge management reduces the need for inbound service exposure, but it does not remove every platform-to-site network dependency. image: /assets/img/v3/architecture/01-high-level.png image_alt: Nova Vector platform and edge network architecture caption: The architecture separates node-initiated communication from functions that require direct reachability to the site. related: - label: Nova Edge url: /edge-computing-platform/ - label: EdgeX Foundry url: /edgex-foundry-platform/ - label: Industrial AI url: /edge-ai-industrial-iot/ ---
