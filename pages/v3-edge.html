A typical node can host EdgeX device services, local application services, Edge AI inference, and the local operator console, but the exact bundle is chosen for the deployment rather than assumed to be identical everywhere. - This is useful when equipment cannot connect directly to the platform, when local processing reduces unnecessary upstream traffic, or when the site must remain useful during periods of limited central connectivity. image: /assets/img/v3/features/07-edge-management/local-console.png image_alt: Nova Vector local edge console caption: Site-side services can be operated locally while remaining part of the managed Nova Edge environment. - eyebrow: Local device layer heading: Use EdgeX where a site benefits from a local device abstraction paragraphs: - EdgeX Foundry device services can communicate with local equipment and expose a common device and command model to the rest of the edge stack. Nova Vector can relate those EdgeX devices back to platform devices and profiles so the site does not become a separate data island. - The supported EdgeX service combination is selected for each project. The platform packages approved EdgeX versions as deployable bundles rather than claiming that every possible community device service is supported automatically. image: /assets/img/v3/features/07-edge-management/edgex-devices.png image_alt: EdgeX devices viewed through Nova Vector caption: EdgeX-connected devices remain visible within the broader Nova Vector operating model. - eyebrow: Local processing heading: Filter and transform data before it leaves the site paragraphs: - Local services can process selected EdgeX or device data close to the process, including transformation, routing, and application-specific logic. The result can then be published upstream through the site's configured messaging path. - This does not turn the edge node into a disconnected second platform. Device identity, approved software, deployment state, and selected telemetry remain tied to the central environment. image: /assets/img/v3/architecture/03-telemetry-path.png image_alt: Nova Vector telemetry architecture caption: Edge-originated telemetry ultimately enters the same normalized data path used by directly connected equipment. - eyebrow: Managed operation heading: Monitor workloads and update sites through the fleet pipeline paragraphs: - The Edge Agent monitors systemd, Docker, and Compose workloads and reports node state back to the platform. Approved bundles can then be deployed through controlled rollout, retry, and rollback workflows. - Fleet onboarding and rollout are integrated beta capabilities. They are best positioned as part of a managed Nova Vector deployment rather than as a standalone replacement for general enterprise device-management software. image: /assets/img/v3/features/07-edge-management/rollout-board.png image_alt: Nova Vector edge fleet rollout board caption: Central rollout control connects the desired software state with actual node deployment results. related: - label: Industrial Edge Management url: /industrial-edge-management/ - label: EdgeX Foundry url: /edgex-foundry-platform/ - label: Platform Architecture url: /architecture/ ---
