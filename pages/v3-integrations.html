That reduces the risk of creating an integration-only copy of the operating model that drifts away from what users see in the platform. - REST is the documented request-response interface, while MQTT, HTTP, and WebSocket provide additional data paths where continuous or event-driven exchange is more appropriate. image: /assets/img/v3/features/11-automation-and-integration/open-api.png image_alt: Nova Vector OpenAPI documentation caption: Documented APIs expose the platform resource model to authenticated external applications. - eyebrow: Commands and schedules heading: Turn repeatable device actions into managed operations paragraphs: - Device commands can be defined once and reused with fixed or calculated values. Scheduled jobs can invoke those commands at configured intervals, which is useful for recurring operational actions that should remain visible and configurable rather than hidden in an external cron script. - Execution remains asynchronous. The platform records and routes the software request, while the final behavior of a remote device depends on the network, adapter, edge node, and physical equipment involved. image: /assets/img/v3/features/11-automation-and-integration/schedules.png image_alt: Nova Vector scheduled operational jobs caption: Schedules expose recurring operational actions as managed platform configuration. - eyebrow: Low-code workflows heading: Use Node-RED for project logic that does not justify a custom service paragraphs: - Node-RED is available for project-specific transformations, routing, rules, and service calls. A flow can subscribe to platform data, reshape payloads, call an external API, and coordinate a custom workflow without modifying the core Nova Vector services. - This makes low-code useful as an integration layer, but it is still project logic. It should be operated, versioned, and supported with the same discipline as other customer-specific integration code. image: /assets/img/v3/features/11-automation-and-integration/automation-result.png image_alt: Nova Vector automation result caption: Automation workflows can connect platform events with project-specific actions and external services. - eyebrow: Custom functions heading: Keep preview capabilities clearly separated from established integration paths paragraphs: - Nova Vector includes a custom-function workspace in preview. It should not yet be positioned as a mature serverless application platform or as a replacement for a customer's existing development environment. - For production integrations, the supported REST, messaging, command, scheduling, and Node-RED paths remain the clearer foundation today. image: /assets/img/v3/architecture/04-events-commands.png image_alt: Nova Vector event and command paths caption: Established integration paths are tied to explicit event, command, and API boundaries. related: - label: REST API url: /api/ - label: Developers url: /developers/ - label: Platform Architecture url: /architecture/ ---
