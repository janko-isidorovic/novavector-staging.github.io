Before a run starts, preflight checks identify missing inputs; during execution, the simulator records state changes and the values that caused them. - This makes the process model inspectable. Engineers can see not only the resulting state but also why the state changed, which is useful when validating logic, diagnosing unexpected behavior, or training people on a process before touching live equipment. image: /assets/img/v3/features/05-process-simulator/simulation-running.png image_alt: Nova Vector process simulation running caption: A simulation run executes versioned process logic against selected inputs and records each transition. - eyebrow: Historical replay heading: Reconstruct a run instead of relying on memory or screenshots paragraphs: - Completed simulations can be reconstructed from their execution history and compared with other runs or process versions. Historical data can also be replayed faster than real time, allowing teams to investigate a past sequence or test how revised logic would interpret the same input. - The value is not a photorealistic digital twin. It is a repeatable operational model whose state transitions can be explained, reproduced, and compared. image: /assets/img/v3/features/05-process-simulator/compare-runs.png image_alt: Nova Vector simulation run comparison caption: Run comparison helps engineers see how process versions behave against comparable inputs. - eyebrow: Protocol simulators heading: Exercise the real adapter path without waiting for production equipment paragraphs: - The simulator suite stands outside Nova Vector and communicates through real protocols. Reference services can emulate Modbus TCP, BACnet/IP, SNMP, MQTT, Sparkplug B, and OPC UA systems so discovery, addressing, decoding, writes, alarms, commands, and downstream workflows are tested through the same integration boundary used in production. - This is useful during demonstrations, pilots, engineering workshops, and acceptance testing because a realistic device environment can be reproduced without shipping the customer's physical equipment into a lab. image: /assets/img/v3/features/10-simulators/assembly-line.png image_alt: Nova Vector serialized assembly-line simulator caption: Reference systems provide repeatable device and production scenarios for integration testing. - eyebrow: Fault and resilience testing heading: Introduce failures deliberately before they happen in the field paragraphs: - Simulator scenarios can change signals, trigger faults, and assert expected outcomes. Network impairment can add delay, jitter, packet loss, reordering, or a complete partition, making it possible to observe how the wider workflow behaves under difficult conditions. - Reference environments currently include a battery-energy-storage enclosure, a bottling or production line, and a serialized assembly-line scenario with RFID operators. image: /assets/img/v3/features/10-simulators/scenario-results.png image_alt: Nova Vector simulator scenario results caption: Scenario results compare the scripted event sequence with the expected operational response. related: - label: Process Automation url: /industrial-state-machine/ - label: Device Connectivity url: /iot-device-management/ - label: Platform Architecture url: /architecture/ ---
